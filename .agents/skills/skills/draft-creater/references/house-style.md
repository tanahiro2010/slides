# 既存ドラフトから借りるもの

**借りるのは形式だけ。** 口調・言い回し・自己紹介の中身は題材ごとに決める。

| 借りる | 借りない |
| --- | --- |
| 節の構成と並び | 書き手固有の言い回し |
| ネストの深さと粒度 | 一人称の選び方 |
| 1 節あたりの分量 | 趣味・ネタの持ち込み方 |
| 記号の使い分け | 締めの決まり文句 |
| 表とコードの入れ方 | 題材固有の結論 |

## 実物を開く

```sh
ls slides/slides/        # 検証系
ls slides/speakerdeck/   # LT 系

# 検証系の節構成を見る
grep -n '^#\{2,3\} ' "slides/slides/Google OAuthがDPoPに対応したらしいので検証してみる/draft.md"

# LT 系の本体を見る
sed -n '/^## 記事・スライド共通ドラフト/,$p' "slides/speakerdeck/個人開発者よ、Honoを使え/draft.md"
```

## 規模の目安

| | 行数 | 節 / スライド数 |
| --- | ---: | --- |
| 検証系 | 400〜760 | `##` 節 10〜15 + メモ |
| LT 系 | 100〜300 | トップレベル項目 15〜25 |

薄いものもある（30 行）。**題材に対して足りていれば短くてよい。**

## 節の構成は揺れる

固定なのは少ない。揃えにこだわらず、中身が書けているかで判断する。

### 検証系

| 節 | 出現 |
| --- | --- |
| `## 一次ソース` | ほぼ全部。更新日付きで |
| `## 表現のルール（slide でも守る）` | 多い。一番あとで効く |
| `## タイトルまわり` | 多い |
| `## つかみ` | 多い |
| `## この発表のスタンス` | 多い |
| 採番した `##` / `###` 節 | 本体 |
| `## メモ（サンプルコード・資料）` | 多い。長いコードの逃がし先 |
| `## 検証前チェックリスト` | 任意 |

### LT 系

| 節 | 出現 |
| --- | --- |
| `## 概要` | 全部 |
| `## LTスライドを作るに当たって` | 多い。`## 30分発表の…` の揺れあり |
| `## 記事を書くに当たって` | 多い |
| `## 記事・スライド共通ドラフト` | 多い。`## スライド内容` のこともある |
| `## 記事ドラフト` / `## 記事詳細ドラフト` | 任意 |

## ネストの深さ

2 段が基本、具体を入れるところで 3〜4 段。

```markdown
- WebMCPとMCPの違い 2              <- 1 段目: スライド / 論点
  - 初期登録の場所とセッション期間      <- 2 段目: 何が違うか
    - MCP は exit するまで使える       <- 3 段目: 中身
      - ページを開いている間だけ        <- 4 段目: 補足
```

深い段には**具体物**が来る。数値、URL、ファイルパス、引用。
4 段を超えたら、その項目はスライド 1 枚分あるということ。割る。

## 項目の粒度

トップレベルは短い見出し。**きれいな章立てにしなくていい。**

```markdown
- 個人開発の敵は「複雑さ」
- 実例紹介：やすみ？
- そういうわけでもない
- 余談だけど...
```

話の流れそのままでよい。繋ぎもスライドになる。

## 表の使い方

**実測値の比較に使う。** 推測や方針を並べない。

```markdown
  | | µs/op | ops/s |
  | --- | ---: | ---: |
  | sign | 26.2 | 38,227 |
  | verify | 50.5 | 19,787 |
```

数値は右寄せ（`---:`）。表の直後に「そこから言えること」を 1 行足す。

## コードの逃がし方

本文に長いコードを置かない。`## メモ` に `### メモ⑬` として置き、
本文からは `📋 メモ⑬` で参照する。

本文に置いてよいのは 5 行程度まで。

## 検証プロジェクトから起こす場合

`verify-pipeline` を回した後なら、素材は `claims.md` と `references.md` にある。
**そのまま貼らない。**

| claims.md | draft.md |
| --- | --- |
| 判定記号付きの主張一覧 | 発表で見せる比較表 |
| `A5c ✅ ツール名だけなら fallback する` | 切断位置の行として並べる |
| 「記事の軸」「使わない発見」 | **書かない**。draft に編集方針は載せない |
| 一次資料の表 | `## 一次ソース` にそのまま使える |
| 「探したが取れなかったもの」 | `## この発表のスタンス` の「できなかったと書く」に効く |

数値は draft に写す。あとで `claims.md` を開き直さずに書けるように。
