# summary-creater

`draft.md` は箇条書き。`article.md` は文章。
**その間で 1 回、文章にしながら事実を確かめる。**

出力は `<デッキ>/summary.md`。雛形は `references/template.md`。

## なぜ間に 1 枚挟むのか

**箇条書きは、繋がっていない主張を隠す。**

```markdown
- ツール名だけ届いた → 切り替わる
- 本文が 1 文字出た → 切り替わらない
```

並べると筋が通って見える。文章にすると詰まる。

> ツール名が届いた段階では切り替わるが、本文が 1 文字出ると切り替わらない。
> **なぜなら——**

ここで止まる。理由を書いていなかったことに、文章にして初めて気づく。
箇条書きのまま `article-creater` に渡すと、**この穴が「無難な一般論」で埋まる。**

同じことが事実にも起きる。「速かった」「らしい」「たしか」は、
箇条書きなら通るが、文章にすると出どころを書く場所が要る。

## 置き場所

```
slides/<group>/<名前>/
├── draft.md       ← 入力
├── summary.md     ← これを作る
├── references.md  調査メモ（あれば入力）
├── claims.md      検証結果（あれば入力）
├── slide.md       別系統。draft から直接作る
└── article.md     summary を読んで作る
```

## Workflow

1. `draft.md` を読む。`references.md` / `claims.md` があれば一緒に読む
2. **draft の順に、段落で書き下す。** 箇条書きを文に変えるだけではなく、繋ぐ
3. **事実が出てくるたびに、出どころを確かめる**（下記）
4. 確かめられなかったものに印をつける。**消さない**
5. 詰まった箇所を「埋まらなかった穴」に書き出す
6. `summary.md` に書く

## 事実を確かめる

文章の中に事実が出てきたら、その場で止めて確かめる。

| 種類 | 確かめ方 |
| --- | --- |
| 自分で測った数値 | `claims.md` / `sandbox/` の記録に当たる。**記録が無ければ測り直す** |
| バージョン・日付 | レジストリ API、リリースノート、コミット日 |
| 仕様の記述 | 一次ドキュメントの原文を引く。要約を信じない |
| 他人の主張 | 出どころを書く。「〇〇によると」 |
| 自分の体験 | 確認不要。ただし**体験だと分かるように書く** |

### 記号

| | 意味 |
| --- | --- |
| （印なし） | 裏が取れている |
| `<!-- 未確認: ... -->` | 確かめられなかった。記事では落とすか「確認できていない」と書く |
| `<!-- 要出典: ... -->` | 言えそうだが出どころが無い |
| `<!-- 穴: ... -->` | 文章にして詰まった。論理が繋がっていない |

**コメントで書く。** 本文に混ぜない。`article-creater` が読んで判断する。

### 主張が崩れたら draft に戻る

文章にすると、**draft の時点では気づかなかった矛盾が出る。**
そのときは静かに言い換えない。

- `draft.md` の該当行を直す
- `summary.md` に「なぜ変えたか」を残す
- 検証プロジェクトなら `claims.md` の判定も直す

**崩れた主張を薄めて残すのが一番まずい。** 落とすか、直すか、どちらかにする。

## 書き方

### draft の順を守る

並べ替えたくなったら、それは `draft.md` の順が悪い。
**draft を直してから書く。** summary で勝手に組み替えると、スライドと記事がずれる。

### 段落で書く

1 文 1 行で改行する。ダッシュや中黒は使わない。
箇条書きは、実測値の比較など一覧性が要るところだけに残す。

### 口調は記事に寄せる

`draft.md` は発表者の声（「じゃあなんでやねん」）。
`summary.md` は記事の声に落とす。ただし**主張の強さは変えない。**

| draft | summary |
| --- | --- |
| 「じゃあなんでPHPの標準はそれに従ってないねん」 | PHP の標準関数はこの規定に従っていない。理由は 2 つある。 |
| なんか謎のおばちゃん登場！ | ブースに、見知らぬ年配の女性がやってきた。 |

**弱めない。** 「〜かもしれない」で逃げると、記事も逃げる。

### 長さ

draft の各項目が 1〜3 段落になる目安。
`article.md` はこれをさらに増量するので、**ここで書き切らない。**

## よくある失敗

- **箇条書きのまま文を足す。** 繋がっていないことに気づけない
- **詰まった箇所を一般論で埋める。** そこが一番書くべき場所
- **裏が取れないものを静かに消す。** 印をつけて残す。消すと誰も気づかない
- **崩れた主張を薄めて残す。** 落とすか直すか
- **口調に引きずられて主張を弱める。** 声は変えても、強さは変えない
- **ここで書き切る。** `article.md` の仕事が無くなる
