# verify-pipeline

「ベンダーが X と書いている。本当か？」を、記事と登壇資料になるまで回す。

このスキルは**順番とゲートだけ**を持つ。各フェーズの中身は専用スキルにある。

```
0. 仕込み          人間への依頼を先に集める / 記録を先に仕込む
1. 調べる          references-creater   → references.md
2. 主張を割る      verify-claims        → claims.md
3. 実機なしで潰す  （ここが一番コスパがいい）
4. コードを書く    verify-harness       → sandbox/
5. 実機で測る      （人間の手が要る）
6. 判定する        verify-judge         → claims.md に書き戻す
7. 開示する        verify-judge         → REPORT.md / 証跡バンドル（要るときだけ）
8. 書く            slide-creater → article-creater
```

**各フェーズの終わりにゲートがある。通らないまま次へ行かない。**
この順番を崩すと、記事を書いた後に全部スクラブして書き直す羽目になる（実際になった）。

---

## 0. 仕込み

### 人間への依頼を先に集める

**この流れは人間待ちで何度も止まる。** 止まる場所は最初から分かっているので、
**フェーズ 0 でまとめて聞く**。後出しにすると往復が増える。

| 要るもの | いつ必要か | 聞いておくこと |
| --- | --- | --- |
| テスト用の認証情報 | フェーズ 5 | 専用クライアント / テストアカウントを作ってもらう |
| ブラウザ操作 | フェーズ 5 | 認可フローは人間が踏む。**やり直しに再認可が要るか**も |
| 報告するかの判断 | フェーズ 7 | 重大な発見が出たら聞く、と先に伝えておく |
| 公開するかの判断 | フェーズ 8 | `published` を立てるのは人間 |

### 記録を先に仕込む

**「あとで JSON に残しておけばよかった」は必ず来る。** 1 行目から入れる
（`verify-harness` の `references/recorder.md`）。

### `.gitignore` を先に書く

`.env` を作る**前**に書く。`data/`・生ログ・退避先・scratch ファイルも最初から除外する。

> ⚠️ 公開リポジトリなら、この時点で「発見が出たら一旦隠す」前提で設計しておく。
> 後から剥がすのは高い。

**ゲート:** 人間への依頼を投げた / レコーダの骨格がある / `.gitignore` が先にある

---

## 1. 調べる → `references-creater`

一次ソースを集める。**更新日を必ず記録する**（後で「どちらを先に疑うか」に効く）。

**ゲート:** 一次資料が表になっている / 各資料の更新日がある

---

## 2. 主張を割る → `verify-claims`

`claims.md` を作る。1 文を複数の主張に割り、確かめ方と**対照**を書く。

**ゲート:**

- [ ] 対照の列が埋まっている（空なら、その検証は結論が出せない）
- [ ] **1 回しか試せない検証を特定した**（やり直しに再認可が要るもの）
- [ ] 実機が要る項目と、要らない項目を分けた

---

## 3. 実機なしで潰す

**ここを飛ばさない。認証情報が来る前に、かなり取れる。**

今回これだけ出た。全部ブラウザも認証情報も無しで取れている。

| 取れたもの | 方法 |
| --- | --- |
| 公式サンプルの署名が壊れている | サンプルをデコードして署名検証 |
| サンプルが他所の例文の丸写し | 埋め込み値（URL・日付）を見る |
| 発表とリリースの 5 ヶ月ズレ | Wayback Machine でドキュメント改版を追う |
| ドキュメント同士の矛盾 | 2 ページを突き合わせて読む |
| 機械可読な対応宣言が無い | metadata / discovery を引いて grep |
| ライブラリの依存・サイズ | レジストリ API |
| 性能の主張の裏取り | 手元でベンチ |

**記事の山場がここで出ることがある。** 今回も「公式サンプルが壊れている」は
認証情報より先に出た。

**ゲート:** 実機不要の項目が全部 ✅/❌/📭 になった

---

## 4. コードを書く → `verify-harness`

`sandbox/` を作る。

**ゲート:**

- [ ] 全送信がレコーダを通る（直 `fetch` が残っていない）
- [ ] 対照が同じスクリプトに入っている
- [ ] 長時間測定は中断・再開できる
- [ ] 通信層が例外を投げない（400 も結果として返る）

---

## 5. 実機で測る

**順番が効く。** 間違えると、やり直しのたびに認可からになる。

```
① 1 回しか試せない検証      ← 認可直後にしか測れないもの
② 失敗ケース一式            ← 壊した入力を投げ分ける
③ 境界の二分探索            ← 1 秒まで詰める
④ 長時間測定                ← 放置できるので最後に回す
⑤ 最後にもう一度 正常系      ← ここまでの結果が有効だと示す
```

⑤ を忘れない。**途中で対象が無効化されていたら、それまでの観測が全部疑わしくなる。**

**ゲート:**

- [ ] ログに残っていない観測が無い（内側の呼び出しも記録されているか）
- [ ] 対照が実際に効いている（でたらめな入力が弾かれているか）
- [ ] 最後の正常系が通っている

---

## 6. 判定する → `verify-judge`

観測と解釈を分け、主張を最小に狭め、独立に再現する。

**ゲート:**

- [ ] 対照の無い観測から結論を書いていない
- [ ] 主張に隠れた `かつ` が無い（複数条件なら全部測ったか）
- [ ] 重い主張は**ゼロからやり直して**再現した
- [ ] 深刻度を盛っていない

ここで判定が覆ることがある。**覆ったら戻る。** 先に進まない。

---

## 7. 開示する（要るときだけ）

セキュリティ上の発見が出たときだけ。手順は `verify-judge/references/disclosure.md`。

```
公開素材から外す → 報告 → 回答を待つ → 公開する
```

**ゲート:**

- [ ] 作業ツリー / 全履歴のファイル / **コミットメッセージ** の 3 箇所を grep した
- [ ] バックアップ（tag + bundle をリポジトリ外）を取った
- [ ] 報告した
- [ ] **回答が返ってきた** ← これが無いと 8 に進めない

> ⚠️ 却下されても結論の一部。理由ごと記事に書くと、むしろ主張が強くなる。

---

## 8. 書く → `slide-creater`（または `yusukebe-creater`）→ `article-creater`

**スライドが先、記事が後。** 記事はスライドの各セクションを増量したもの。

ここで**記事の軸を 1 本に決める**。検証プロジェクトは発見が多いので、
放っておくと主張が 2 本になって絡まる。

実際に絡まった。結論ブロックの箇条書きが「公式がズレてる」なのに、
一番伝えたいことが「守備範囲が狭い」だった。**別の記事の結論が同居していた。**

決め方:

- 全発見を**1 文の主張**の下に並べられるか試す
- 並ばない発見は、**脇道として明示**するか落とす
- 「導入すべきか」は読者が必ず持つ疑問だが、**末尾に 1 節**に集約する。
  本編に散らすと軸がぼやける

**ゲート:** 結論ブロックの主張と、一番伝えたいことが**同じ 1 本**になっている

---

## どこまで来たかを残す

**この流れは 1 セッションで終わらない。** `claims.md` の先頭に状態を置く。

```markdown
| | |
| --- | --- |
| フェーズ | 5（実機で測る）まで完了 |
| 次 | 6. 判定 — nonce の寿命が未測定なので主張を狭める |
| 人間待ち | なし |
| 開示 | 報告済み・回答待ち |
```

セッションをまたぐとき、**次の 1 手を文で書いておく**。

---

## よくある失敗

- **実機待ちで止まる** — フェーズ 3 で取れるものを先に潰す
- **人間への依頼を小出しにする** — フェーズ 0 でまとめて聞く
- **1 回しか試せない検証を後回しにする** — 認可からやり直しになる
- **記録を後から足す** — 一番欲しかった最初の run が記録なしで終わる
- **判定が覆ったのに先へ進む** — 戻る。記事を書いてから覆ると高くつく
- **開示の前に公開する** — 順番が逆。コミットメッセージも漏れる
- **記事の軸を決めずに書き始める** — 主張が 2 本になって絡まる
- **最後の正常系を忘れる** — 対象が無効化されていたら全部疑わしい
